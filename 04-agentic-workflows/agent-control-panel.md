## What Juno Is Doing

Juno works on insight synthesis: it turns scattered customer signals into evidence for a feature idea, which the PM confirms or dismisses.

## Four Levers

**Stop Conditions** (Loop):

max_steps: 25 tool calls per analysis.
Abort if the same tool fails 2x in a row or 3 quotes in a row fail the
word-for-word check.
Hard timeout: 60s wall clock.

**Structured Tool Outputs** (Tools):

| Tool | On success | On failure |
|---|---|---|
| search_sources | status: ok · results [source_id, date, snippet] · count · sources_searched / sources_reachable | status: error · failed_source · reason |
| read_source | status: ok · source_id · date · full text | status: not_found / unreachable · source_id |
| extract_passage | status: ok · passage · start/end position · verbatim: true | status: failed · verbatim: false |
| score_match | status: ok · score 0–100 | status: failed · score: null |
| create_requirement / link_evidence / update_requirement | status: ok · item_id | status: failed · reason · locked: true/false |
| re_analyze | status: ok · requirement_id · count of new matches | status: failed · reason |

A search with count 0 counts as "no evidence" only if
sources_searched = sources_reachable = all sources; otherwise it is "not fully checked".

**Confidence Thresholds** (Verification):

- **High (match score ≥ 80):** Juno shows it as an AI-identified match.
- **Medium (50–79):** shown, but labeled "weak match – check source" for the PM.
- **Low (< 50):** not shown as evidence; if nothing better exists, the
  requirement becomes "no evidence found".

Evidence based only on sales claims or executive emails is capped at Medium.

**North Star** (Context):

Find real customer evidence for the PM's feature idea and link every claim to a
verbatim source passage; never invent a source, quote or customer, and never
treat a sales promise or executive wish as proof of customer need.

## Rules of Engagement

**Agency Permission:**

Can decide alone: search and read sources, create and link AI-identified
requirements and evidence, score matches, re-analyze its own items.
Must propose and wait: every match stays "AI-identified" until the PM confirms
or dismisses it. Cannot change anything a human has edited, confirmed or dismissed.

**Access Control:**

Juno sees only what the requesting PM can see (inherits their permissions,
no service account with company-wide access).
Read-only: call transcripts, Jira, support tickets, CRM notes, public Slack
channels, emails sent to the product team, strategy, roadmap and pipeline docs.
Read and write: only Juno's own requirements and evidence inside the tool.
No access: private Slack channels, DMs, HR data, billing and invoice data.

**Fallback Protocols:**

```markdown
- max_steps or timeout reached: stop, show verified results, mark the rest
  "not fully checked".
- Same tool fails 2x: skip that tool and name the failed source.
- 3 quotes fail verification: abort, discard unverified matches, tell the PM.
Only a PM click on "Re-analyze" starts a new run.
```

**Checkpoints:**

```markdown
- After every analysis: PM confirms or dismisses each match.
- Contradicting sources: Juno pauses until the PM decides.
- Nothing leaves the tool without PM review.
```
